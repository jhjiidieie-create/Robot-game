**Состав:** 9 C#-скриптов.

## 1. Что делает проект

Это VR-игра с роботом, который собирается из четырёх функциональных деталей, допускается к запуску только после правильной сборки и размещения в стартовой зоне, а затем сортирует шайбы по соответствующим ячейкам.

В проекте предусмотрены два способа управления роботом:

1. **Автоматический режим** — робот использует NavMeshAgent, самостоятельно ищет ближайшую подходящую шайбу, подбирает её и доставляет в свободную ячейку с совпадающим номером.
2. **Ручной режим** — игрок управляет движением робота через SteamVR Input Actions левой рукой, подбирает шайбу действием Magnet и отпускает действием Release.

Общий игровой цикл:

1. Игрок берёт детали с помощью VR-взаимодействия.
2. Устанавливает детали в соответствующие точки крепления.
3. Помещает робота в стартовую зону.
4. Нажимает кнопку запуска, которая должна вызывать именно `RobotAssembly.StartRobot()`.
5. Сборка проверяется.
6. Запускается выбранный режим робота и игровой таймер.
7. Робот подбирает шайбы и размещает их по номерам.
8. При сортировке всех шайб или по окончании времени игра завершается, робот останавливается и появляется панель результата.

## 2. Архитектура и связи скриптов

| Скрипт | Ответственность |
|---|---|
| `GameManager` | Таймер, подсчёт отсортированных шайб, завершение и перезапуск сцены |
| `RobotAssembly` | Проверка полноты сборки и стартовой зоны, запуск режимов робота |
| `RobotMountPoint` | Установка удерживаемой VR-детали в точку крепления |
| `RobotPart` | Тип детали и флаг установленного состояния |
| `StartZone` | Отслеживание присутствия объектов в стартовом Trigger |
| `Puck` | Номер шайбы и её состояние |
| `PuckSlot` | Проверка номера шайбы и регистрация заполнения ячейки |
| `RobotController` | Автоматическая навигация, подбор и доставка шайб |
| `ManualRobotController` | Ручное движение, захват и отпускание шайбы |

### Основные зависимости

- `RobotAssembly` ссылается на четыре `RobotMountPoint`, `StartZone`, оба контроллера и `GameManager`.
- Каждый `RobotMountPoint` знает требуемый тип `RobotPart`.
- `RobotController` работает с массивами `Puck` и `PuckSlot`.
- `ManualRobotController` получает массив шайб из Inspector.
- `PuckSlot` сообщает `GameManager` об успешном заполнении.
- `GameManager` останавливает автоматический и ручной контроллеры.
- `RobotPart` и `Puck` — простые компоненты данных, не управляющие объектами самостоятельно.

### Схема вызовов

```text
Кнопка запуска
    |
    v
RobotAssembly.StartRobot()
    |
    +--> проверка Motor / PowerSupply / Manipulator / Tracks
    |
    +--> проверка StartZone
    |
    +--> RobotController.StartRobot() ----> GameManager.StartGame()
    |          |
    |          +--> поиск шайбы и ячейки
    |
    +--> ManualRobotController.StartRobot()
               |
               +--> GameManager.StartGame()

PuckSlot.OnTriggerEnter()
    |
    +--> GameManager.AddPuck()
              |
              +--> при достижении общего количества: EndGame()
                         |
                         +--> остановка обоих контроллеров
                         +--> показ результата
```

**Критически важная настройка:** кнопка запуска должна вызывать `RobotAssembly.StartRobot()`, а не напрямую `RobotController.StartRobot()`. Прямой вызов контроллера обходит проверку деталей и стартовой зоны.

## 3. Разбор каждого скрипта

## 3.1 GameManager.cs

**Назначение:** центральное управление игровой сессией: старт таймера, отображение времени, подсчёт отсортированных шайб, завершение игры и перезапуск сцены.

### Код построчно

```csharp
using UnityEngine;
```
Подключает базовые типы Unity: `MonoBehaviour`, `GameObject`, `Time`, `Mathf`, `FindObjectsOfType` и другие.

```csharp
using UnityEngine.SceneManagement;
```
Подключает управление сценами. В этом скрипте используется для перезагрузки текущей сцены.

```csharp
using TMPro;
```
Подключает TextMeshPro. Он нужен для вывода таймера и результата в UI.

```csharp
public class GameManager : MonoBehaviour
```
Объявляет компонент Unity. Благодаря наследованию от `MonoBehaviour` скрипт можно добавить на GameObject, а Unity вызывает его методы жизненного цикла.

```csharp
public float timeLimit = 30f;
```
Публичная продолжительность раунда в секундах. Значение можно менять в Inspector. По умолчанию — 30 секунд. Суффикс `f` означает тип `float`.

```csharp
public TMP_Text timerText, resultText;
```
Две ссылки на UI-текст TextMeshPro:
- `timerText` — показывает оставшееся время;
- `resultText` — показывает результат в формате «отсортировано из общего количества».

Обе ссылки нужно назначить в Inspector.

```csharp
public GameObject resultPanel;
```
Ссылка на панель результата. В начале игры она скрывается, при завершении показывается.

```csharp
public RobotController robot;
public ManualRobotController manualRobot;
```
Ссылки на автоматический и ручной контроллеры. Они нужны для остановки робота при завершении игры. Обе ссылки могут быть назначены; тогда при завершении будут остановлены оба компонента.

```csharp
int totalPucks, sortedPucks;
```
Два целочисленных счётчика:
- `totalPucks` — общее число шайб, найденных в сцене при запуске объекта GameManager;
- `sortedPucks` — число зарегистрированных успешных сортировок.

Они закрытые, потому что не имеют модификатора `public`.

```csharp
float timeLeft;
bool active;
```
- `timeLeft` — текущее оставшееся время;
- `active` — флаг активности игровой сессии. Если он false, таймер не обновляется.

```csharp
void Start()
```
Unity вызывает этот метод при запуске компонента.

```csharp
totalPucks = FindObjectsOfType<Puck>().Length;
```
Находит активные в сцене компоненты `Puck` и записывает длину полученного массива. То есть количество шайб фиксируется один раз при старте GameManager. Шайбы, созданные позднее, в это число автоматически не попадут.

```csharp
resultPanel.SetActive(false);
```
Скрывает панель результата. Ссылка `resultPanel` обязательна, иначе возникнет NullReferenceException.

```csharp
ShowTime(timeLimit);
```
Показывает исходное значение таймера до начала раунда.

```csharp
void Update()
```
Вызывается Unity каждый кадр.

```csharp
if (!active) return;
```
Если игра не активна, метод немедленно завершается. Это не позволяет таймеру идти до старта.

```csharp
ShowTime(timeLeft -= Time.deltaTime);
```
Сначала уменьшает `timeLeft` на время прошедшее с прошлого кадра, затем передаёт новое значение в `ShowTime`. `Time.deltaTime` обеспечивает отсчёт в секундах, а не в кадрах. Таймер зависит от игрового времени Unity и замедлится/остановится при изменении `Time.timeScale`.

```csharp
if (timeLeft <= 0) EndGame();
```
Когда время достигает нуля или становится отрицательным, вызывается завершение игры.

```csharp
public void StartGame()
```
Публичный метод старта. Его вызывают контроллеры робота.

```csharp
if (active) return;
```
Не позволяет повторно запускать уже активный раунд.

```csharp
timeLeft = timeLimit;
active = true;
ShowTime(timeLeft);
```
Сбрасывает оставшееся время к лимиту, включает игровой флаг и сразу обновляет UI.

```csharp
public bool AddPuck()
```
Метод регистрации отсортированной шайбы. Возвращает `bool`: false, если игра ещё не завершилась; true, если после добавления шайбы игра завершилась.

```csharp
if (!active || ++sortedPucks < totalPucks) return false;
```
Если игра не активна, метод ничего не засчитывает. Иначе сначала увеличивает `sortedPucks`, затем сравнивает его с общим количеством. Пока отсортировано меньше общего числа, возвращает false.

Оператор `++` увеличивает значение на единицу до сравнения, поскольку используется в префиксной форме.

```csharp
EndGame();
return true;
```
Если достигнуто или превышено общее число, завершает игру и сообщает вызывающему коду, что раунд окончен.

```csharp
void EndGame()
```
Закрытый метод завершения игровой сессии.

```csharp
active = false;
```
Отключает дальнейшее обновление таймера и приём новых шайб через `AddPuck`.

```csharp
if (robot != null) robot.StopRobot();
if (manualRobot != null) manualRobot.StopRobot();
```
Проверяет наличие ссылок и останавливает соответствующие контроллеры. Если оба назначены, останавливаются оба.

```csharp
resultText.text = $"{sortedPucks} из {totalPucks}";
```
Записывает итоговую строку в TextMeshPro. Интерполяция строк `$"..."` вставляет значения переменных.

```csharp
resultPanel.SetActive(true);
```
Показывает панель результата.

```csharp
void ShowTime(float time)
```
Вспомогательный метод форматирования и вывода времени.

```csharp
int seconds = Mathf.Max(0, Mathf.CeilToInt(time));
```
Округляет время вверх до целой секунды и не позволяет показать отрицательное значение. Например, 4.1 отображается как 5, а -0.2 — как 0.

```csharp
timerText.text = $"{seconds / 60}:{seconds % 60:00}";
```
Формирует минуты и секунды:
- `seconds / 60` — целое количество минут;
- `seconds % 60` — остаток секунд;
- `:00` — формат из двух цифр, например 0:09.

```csharp
public void Restart() => SceneManager.LoadScene(SceneManager.GetActiveScene().buildIndex);
```
Короткая запись метода. Получает индекс текущей сцены и загружает её заново. Кнопка Restart в UI должна вызывать этот метод. Сцена должна быть добавлена в Build Settings / список сцен сборки.

### Настройки Inspector для GameManager

| Поле | Что назначить |
|---|---|
| Time Limit | Продолжительность раунда в секундах |
| Timer Text | TMP-текст таймера |
| Result Text | TMP-текст результата |
| Result Panel | Панель, которая скрыта до конца раунда |
| Robot | Компонент автоматического контроллера |
| Manual Robot | Компонент ручного контроллера |

### Важные особенности
- Общее количество шайб считается один раз в `Start()`.
- `sortedPucks` не сбрасывается в `StartGame()`. Повторный запуск без перезагрузки сцены не начинает полностью новую сессию.
- `StartGame()` не скрывает панель результата. Для полноценного нового раунда предусмотрен перезапуск сцены через `Restart()`.
- Если `totalPucks == 0`, автоматического завершения при старте не произойдёт: завершение проверяется при вызове `AddPuck()` или по таймеру.
- `timerText`, `resultText` и `resultPanel` должны быть назначены, поскольку в коде нет проверки на null для этих UI-ссылок.

## 3.2 ManualRobotController.cs

**Назначение:** ручное управление роботом через SteamVR, поиск ближайшей доступной шайбы в радиусе захвата, прикрепление её к точке переноса и отпускание.

### Код построчно

```csharp
using UnityEngine;
```
Подключает Unity API: Transform, Rigidbody, Collider, Time и другие типы.

```csharp
using Valve.VR;
```
Подключает SteamVR Input API: источники ввода, действия и чтение состояний кнопок.

```csharp
public class ManualRobotController : MonoBehaviour
```
Компонент ручного управления, который добавляется на объект робота.

```csharp
public Transform carryPoint;
```
Точка, к которой прикрепляется переносимая шайба. Обычно это дочерний Transform робота в месте захвата. Нужно назначить в Inspector.

```csharp
public Puck[] pucks;
```
Массив шайб, доступных для ручного захвата. Его нужно заполнить в Inspector. В отличие от автоматического режима, здесь массив не ищется автоматически.

```csharp
public float moveSpeed = 2f, turnSpeed = 90f, grabDistance = 1f;
```
Настройки:
- `moveSpeed` — скорость движения;
- `turnSpeed` — скорость поворота в градусах в секунду;
- `grabDistance` — максимальная дистанция поиска шайбы.

```csharp
Puck carriedPuck;
Rigidbody puckRb;
Collider[] puckColliders;
bool active;
```
Внутреннее состояние:
- текущая переносимая шайба;
- её Rigidbody;
- массив её Collider;
- флаг активности ручного управления.

```csharp
public bool IsMoving { get; private set; }
```
Публичное свойство для чтения состояния движения. Из других скриптов значение можно читать, но нельзя напрямую менять. Сам контроллер обновляет его внутри класса.

```csharp
public void StartRobot() => active = true;
```
Включает обработку ручного ввода.

```csharp
public void StopRobot() { active = IsMoving = false; }
```
Отключает ручное управление и сбрасывает флаг движения. Важно: этот метод не отпускает уже захваченную шайбу и не восстанавливает её физику. Это отмечено в аудите ниже.

```csharp
void Update()
```
Каждый кадр проверяет ввод и обновляет движение.

```csharp
if (!active) return;
```
До старта игры контроллер не реагирует на кнопки.

```csharp
var hand = SteamVR_Input_Sources.LeftHand;
```
Выбирает левую руку как источник ввода для всех действий этого контроллера.

```csharp
bool f = SteamVR_Actions.default_Forward.GetState(hand);
bool b = SteamVR_Actions.default_Backward.GetState(hand);
bool l = SteamVR_Actions.default_Left.GetState(hand);
bool r = SteamVR_Actions.default_Right.GetState(hand);
```
Считывает удерживаемое состояние четырёх SteamVR Input Actions:
- Forward — вперёд;
- Backward — назад;
- Left — поворот влево;
- Right — поворот вправо.

Имена действий должны существовать в SteamVR Input и быть корректно привязаны к контроллеру. Одного наличия кода недостаточно — требуется настроенная Input Actions конфигурация SteamVR.

```csharp
transform.Translate(Vector3.forward * ((f ? 1 : 0) - (b ? 1 : 0)) * moveSpeed * Time.deltaTime);
```
Двигает объект по его локальной оси вперёд/назад. Тернарные выражения преобразуют кнопки в числа:
- вперёд без назад: +1;
- назад без вперёд: -1;
- одинаковое состояние: 0.

Скорость умножается на `Time.deltaTime`, поэтому движение не зависит напрямую от частоты кадров. У `Translate` по умолчанию используется локальное пространство объекта.

```csharp
transform.Rotate(Vector3.up, ((r ? 1 : 0) - (l ? 1 : 0)) * turnSpeed * Time.deltaTime);
```
Поворачивает робота вокруг локальной оси Y. Вправо — положительный угол, влево — отрицательный.

```csharp
IsMoving = f || b || l || r;
```
Считает робота движущимся, если нажата хотя бы одна из четырёх клавиш движения/поворота. Даже один поворот устанавливает IsMoving в true.

```csharp
if (SteamVR_Actions.default_Magnet.GetStateDown(hand)) PickUpPuck();
```
При новом нажатии Magnet вызывает подбор. `GetStateDown` срабатывает один раз в момент нажатия, а не всё время удержания.

```csharp
if (SteamVR_Actions.default_Release.GetStateDown(hand)) ReleasePuck();
```
При новом нажатии Release вызывает отпускание шайбы.

### Метод PickUpPuck()

```csharp
if (carriedPuck != null) return;
```
Если шайба уже находится на роботе, новую взять нельзя.

```csharp
float min = grabDistance * grabDistance;
```
Квадрат максимальной дистанции. Сравнение квадратов расстояний позволяет не выполнять дорогой квадратный корень.

```csharp
foreach (Puck puck in pucks)
```
Перебирает все элементы назначенного массива.

```csharp
if (puck == null || puck.isSorted || puck.isCarried) continue;
```
Пропускает отсутствующие элементы, уже отсортированные шайбы и шайбы, которые уже несёт другой контроллер.

```csharp
float d = (carryPoint.position - puck.transform.position).sqrMagnitude;
```
Вычисляет квадрат расстояния от точки захвата до шайбы.

```csharp
if (d >= min) continue;
min = d;
carriedPuck = puck;
```
Если шайба не ближе текущего минимума, пропускает её. Иначе обновляет минимум и выбирает её. В итоге выбирается ближайшая доступная шайба внутри радиуса.

```csharp
if (carriedPuck == null) return;
```
Если подходящая шайба не найдена, метод заканчивается.

```csharp
carriedPuck.isCarried = true;
```
Ставит флаг, чтобы другие системы не пытались взять эту шайбу.

```csharp
puckRb = carriedPuck.GetComponentInChildren<Rigidbody>();
```
Ищет Rigidbody на самой шайбе или в её дочерних объектах. Ссылка сохраняется для восстановления физики при отпускании.

```csharp
puckColliders = carriedPuck.GetComponentsInChildren<Collider>();
```
Получает все Collider в иерархии шайбы. В этой версии вызов не передаёт `true`, поэтому выключенные компоненты обычно не включаются в поиск.

```csharp
puckRb.isKinematic = true;
puckRb.useGravity = false;
```
Переводит Rigidbody в кинематический режим и отключает гравитацию. ВАЖНО: если Rigidbody не найден, обращение к нему вызовет NullReferenceException.

```csharp
foreach (Collider col in puckColliders) col.enabled = false;
```
Выключает коллайдеры шайбы, чтобы при переносе они не сталкивались с окружением.

```csharp
carriedPuck.transform.SetParent(carryPoint);
```
Делает шайбу дочерним объектом точки переноса. Теперь она следует за роботом.

```csharp
carriedPuck.transform.SetLocalPositionAndRotation(Vector3.zero, Quaternion.identity);
```
Устанавливает локальные позицию и поворот шайбы в ноль относительно carryPoint. Шайба точно совмещается с точкой захвата.

### Метод ReleasePuck()

```csharp
if (carriedPuck == null) return;
```
Если робот ничего не несёт, выход.

```csharp
carriedPuck.transform.SetParent(null);
```

```csharp
void Start() => parts = FindObjectsOfType<RobotPart>();
```
При старте находит все активные компоненты RobotPart и сохраняет массив. Новые детали, созданные после этого момента, в массив автоматически не добавятся.

```csharp
void Update()
```
Каждый кадр проверяет, можно ли установить деталь.

```csharp
if (installedPart != null) return;
```
Если точка уже занята, прекращает работу. В этой реализации одна точка принимает только одну деталь и не поддерживает снятие.

```csharp
foreach (RobotPart part in parts)
```
Перебирает заранее найденные детали.

```csharp
if (part == null || part.isAttached || part.partType != requiredType ||
    (transform.position - part.transform.position).sqrMagnitude > attachDistance * attachDistance) continue;
```
Пропускает деталь, если:
- ссылка отсутствует;
- деталь уже установлена;
- тип детали не подходит;
- деталь дальше допустимого радиуса.

Дистанция сравнивается в квадрате, поэтому вычислять корень не нужно.

```csharp
Interactable item = part.GetComponent<Interactable>();
```
Получает SteamVR Interactable на том же GameObject, где находится RobotPart.

```csharp
if (item == null || item.attachedToHand == null) continue;
```
Деталь должна иметь Interactable и в данный момент находиться в руке. Если игрок просто поднёс свободно лежащую деталь к точке, но не держит её, установка не произойдёт.

```csharp
Collider[] partColliders = part.GetComponentsInChildren<Collider>(true);
```
Получает все Collider детали и её дочерних объектов, включая выключенные компоненты (аргумент true).

```csharp
Throwable throwable = part.GetComponent<Throwable>();
Rigidbody rb = part.GetComponent<Rigidbody>();
```
Получает компоненты Throwable и Rigidbody с корневого объекта детали. В дочерних объектах эти компоненты этим кодом не ищутся.

```csharp
item.attachedToHand.DetachObject(part.gameObject, false);
```
Отсоединяет деталь от руки SteamVR. Второй аргумент false означает, что при отсоединении не применяется обычное действие броска/сохранения скорости.

```csharp
item.enabled = false;
```
Отключает Interactable после установки. Деталь больше нельзя взять обычным SteamVR-взаимодействием через этот компонент.

```csharp
if (throwable != null) throwable.enabled = false;
```
Если Throwable присутствует, отключает его, чтобы деталь не могла использовать поведение броска.

```csharp
if (rb != null) { rb.isKinematic = true; rb.useGravity = false; }
```
Если Rigidbody существует, переводит его в кинематический режим и отключает гравитацию.

```csharp
foreach (Collider col in partColliders)
    if (col != null) col.enabled = false;
```
Отключает все коллайдеры детали и её дочерних объектов. Проверка null защищает от отсутствующих ссылок в массиве.

```csharp
part.isAttached = true;
installedPart = part;
```
Помечает саму деталь установленной и сохраняет её в точке крепления. Это состояние используется RobotAssembly для проверки сборки.

```csharp
part.transform.SetParent(transform);
```
Делает деталь дочерней точке крепления.

```csharp
part.transform.SetLocalPositionAndRotation(Vector3.zero, Quaternion.identity);
```
Выравнивает локальную позицию и поворот детали относительно точки крепления.

```csharp
return;
```
После установки одной детали завершает Update. Не позволяет продолжать перебор в этом кадре.

### Настройки Inspector

Для каждой точки крепления:
- назначить `Required Type`;
- задать `Attach Distance`;
- поле `Installed Part` обычно оставить пустым — оно заполняется кодом.

Для деталей:
- добавить `RobotPart` и выбрать правильный `Part Type`;
- добавить SteamVR `Interactable`;
- добавить `Throwable`, если используемая схема захвата/броска SteamVR его требует;
- настроить Rigidbody и Collider;
- проверить, что Interactable, RobotPart и ожидаемый Rigidbody находятся на тех объектах и уровнях иерархии, где их ищет код.

**Особенность финального кода:** после установки строка `item.enabled = false;` отключает Interactable. Если требуется временно разрешить повторное взаимодействие с установленной деталью для теста, эту строку можно временно закомментировать, но тогда нужно отдельно проверить, не конфликтует ли повторный захват с состоянием `isAttached`, выключенными Collider и кинематическим Rigidbody.

## 3.9 StartZone.cs

**Назначение:** отслеживает, находится ли хотя бы один Collider внутри стартовой зоны.

### Разбор кода

```csharp
using UnityEngine;
```
Подключает Unity API.

```csharp
public class StartZone : MonoBehaviour
```
Компонент стартовой зоны.

```csharp
public bool isOccupied;
```
Публичный флаг занятости. Его читает RobotAssembly перед запуском.

```csharp
int objectsInside;
```
Счётчик количества вошедших Collider. Поле закрытое, чтобы изменять его только этим скриптом.

```csharp
void OnTriggerEnter(Collider other) => isOccupied = ++objectsInside > 0;
```
При входе Collider увеличивает счётчик на единицу и устанавливает isOccupied в true, если внутри есть хотя бы один Collider.

```csharp
void OnTriggerExit(Collider other) => isOccupied = (objectsInside = Mathf.Max(0, objectsInside - 1)) > 0;
```
При выходе Collider уменьшает счётчик, но не позволяет ему стать отрицательным. После этого isOccupied показывает, остались ли внутри другие Collider.

### Настройки стартовой зоны
- На объекте должен быть Collider с включённым `Is Trigger`.
- Физические объекты робота должны входить в область Trigger.
- На объекте/иерархии должны быть корректно настроены Collider и Rigidbody согласно правилам Unity Physics.
- StartZone должен быть назначен в RobotAssembly.

**Ограничение текущей реализации:** код не проверяет, кто именно вошёл в зону. Любой объект с Collider может сделать `isOccupied = true` — например, шайба, деталь или рука игрока. Счёт ведётся по Collider, а не по уникальным GameObject или по конкретному роботу.

По директивам `using` в девяти скриптах можно достоверно определить следующие пространства имён:

### Что это означает на практике

Базовая среда проекта. Все компоненты `MonoBehaviour`, Transform, Collider, Rigidbody и физические события относятся к Unity.

**TextMeshPro**
Используется для вывода таймера и результата. В проекте должны быть доступны TMP-компоненты и ресурсы TextMeshPro. В зависимости от версии Unity TextMeshPro может устанавливаться/обновляться через Package Manager как пакет `com.unity.textmeshpro`.

Код использует `NavMeshAgent` из `UnityEngine.AI`. Сам API доступен в Unity, а инструменты построения NavMesh в разных версиях Unity связаны с AI Navigation. Наличие именно пакета AI Navigation и его версия по этим скриптам не подтверждаются.

**SteamVR Plugin**
Код использует SteamVR Input и Interaction System:
- `SteamVR_Input_Sources.LeftHand`;

- `default_Backward`, `default_Left`, `default_Right`;
- `default_Magnet`, `default_Release`;
- `Interactable`;
- `Throwable`.

Это указывает на SteamVR Plugin для Unity. Для работы ручного управления должны существовать соответствующие Input Actions и bindings. Для установки деталей должны быть настроены компоненты SteamVR Interaction System.

В папке 11.0 находятся только C#-скрипты. В ней нет `Packages/manifest.json`, `ProjectSettings/ProjectVersion.txt`, настроек SteamVR Input, сцены или Prefab. Поэтому точные версии Unity, SteamVR Plugin, TextMeshPro и AI Navigation, полный перечень установленных пакетов и настройки проекта по одному этому каталогу установить нельзя. Их нельзя достоверно придумывать.

## 6. Полный аудит кода релиза 11.0

Ниже перечислены потенциальные проблемы, выявленные статическим чтением кода. Это не означает, что все они проявляются в текущей сцене. Приоритет показывает, что стоит проверить в первую очередь.

### 6.1 Высокий приоритет

**1. GameManager может не быть назначен в автоматическом контроллере.**

В `RobotController.StartRobot()` GameManager проверяется на null перед запуском таймера. Но в `DropPuck()` вызывается `gameManager.AddPuck()` без проверки. Если ссылка не назначена, при доставке шайбы произойдёт NullReferenceException.

**Рекомендация:** обязательно назначить GameManager в RobotController Inspector.

**2. Ручной подбор предполагает наличие Rigidbody.**

В `ManualRobotController.PickUpPuck()` результат `GetComponentInChildren<Rigidbody>()` сразу используется без проверки. Если Rigidbody отсутствует, будет NullReferenceException.

**Рекомендация:** у каждой шайбы должен быть Rigidbody в корне или дочерней иерархии. При желании код можно дополнительно защитить проверкой null.

**3. Остановка ручного робота не освобождает захваченную шайбу.**

`ManualRobotController.StopRobot()` отключает ввод, но не вызывает `ReleasePuck()`. Если игра закончится во время переноса, шайба останется дочерней carryPoint, с отключёнными Collider, выключенной гравитацией и кинематическим Rigidbody.

**Рекомендация:** проверить сценарий завершения игры во время удержания шайбы. При необходимости добавить корректную процедуру сброса/фиксации шайбы.

**4. StartZone принимает любой Collider.**

Скрипт не проверяет тег, слой или принадлежность объекта роботу. Любой Collider внутри зоны может разрешить запуск.

**Рекомендация:** если по игровому замыслу запуск разрешён только при нахождении робота в зоне, добавить фильтр по объекту/тегу/слою или отдельному компоненту.

### 6.2 Средний приоритет

**5. RobotMountPoint кэширует детали только в Start().**

Новые детали, появившиеся после запуска сцены, не попадут в массив `parts`. Кроме того, стандартный `FindObjectsOfType` не включает неактивные объекты.

**Рекомендация:** подходит для сцены, где все детали уже размещены и активны при старте. Для динамического спавна нужен способ обновления массива.

**6. RobotController кэширует шайбы и ячейки только при запуске.**

Новые шайбы и ячейки после старта не будут обнаружены автоматическим режимом.

**Рекомендация:** если объекты статичны на протяжении раунда, текущий подход нормален.

**7. В RobotController не проверяется null для элементов массивов.**

В `FindNextPuck()` и `HasFreeSlot()` предполагается, что все элементы массивов существуют. Удалённый объект Unity обычно сравнивается с null, но в цикле нет отдельной защиты для `puck == null` и `slot == null`. Если объекты могут удаляться во время игры, это риск.

**Рекомендация:** добавить null-проверки, если шайбы или ячейки могут уничтожаться динамически.

**8. RobotController не восстанавливает физику шайбы после автоматической доставки.**

При подборе выключаются Collider и физическая динамика. При доставке шайба становится дочерней dropPoint, но Collider не включаются и Rigidbody не переводится обратно в динамический режим.

Это может быть намеренно: отсортированная шайба должна оставаться неподвижной в ячейке. Если по дизайну это ожидаемое поведение, менять ничего не нужно.

**9. PuckSlot может принять шайбу, даже если Drop Point не назначен.**

Сам `PuckSlot.OnTriggerEnter()` проверяет номер и состояние, но не проверяет `dropPoint`. Ручной режим может засчитать шайбу через Trigger даже при пустом Drop Point. Автоматический режим, наоборот, исключает такую ячейку при поиске.

**Рекомендация:** обязательно назначать Drop Point каждой ячейке.

**10. Ручной режим не проверяет соответствие номера шайбы и ячейки до захвата.**

Ручной контроллер может взять любую доступную шайбу. Правильность сортировки определяется Trigger-логикой PuckSlot. Это допустимо, если игрок сам доставляет шайбу в нужное место.

**11. Оба режима могут запускаться одновременно.**

Если в RobotAssembly назначены и automaticRobot, и manualRobot, StartRobot запускает оба. Это может привести к одновременному движению двух систем или конфликту за шайбы, особенно если обе системы используют один набор объектов.

**Рекомендация:** в Inspector назначать только тот контроллер, который должен работать в текущем режиме, либо добавить явный выбор режима.

**12. Повторный старт GameManager не сбрасывает результат.**

StartGame сбрасывает только таймер и active. Он не обнуляет sortedPucks и не скрывает resultPanel. Повторная игровая сессия в той же сцене некорректна без дополнительного сброса состояния.

**Рекомендация:** использовать Restart с перезагрузкой сцены для новой полноценной попытки — это соответствует текущей реализации.

### 6.3 Низкий приоритет / особенности реализации

**13. `FindObjectsOfType` устаревает в новых версиях Unity.**

В современных версиях Unity API может быть помечен obsolete в пользу `FindObjectsByType`. Это не обязательно ошибка текущей версии проекта. Не менять без проверки версии Unity и совместимости.

**14. StartZone считает Collider, а не уникальные объекты.**

Если у робота несколько Collider, счётчик увеличится несколько раз. Обычно это не ломает сам флаг: пока все коллайдеры не выйдут, зона останется занятой. Но при сложной иерархии, отключении Collider или уничтожении объекта без корректного OnTriggerExit возможна рассинхронизация счётчика.

**15. RobotMountPoint отключает все Collider детали.**

Это предотвращает физические конфликты после установки. Но если в проекте нужны визуальные или Trigger Collider для дальнейшей логики, они тоже выключатся.

**16. RobotMountPoint ищет Interactable, Throwable и Rigidbody на корне RobotPart.**

Если компоненты размещены на дочерних объектах, текущий код их не найдёт. Для Collider, напротив, используется поиск по всей иерархии.

**17. RobotController не проверяет успешность SetDestination.**

Если цель не достижима или агент не находится на NavMesh, назначение пути может не сработать корректно. Требуется тестирование на реальной сцене и проверка `agent.isOnNavMesh`, результата SetDestination и состояния пути при необходимости.

**18. RobotController при отсутствии свободной ячейки может остаться с шайбой.**

Если после подбора не найден targetSlot, метод FindNextSlot завершится. Робот останется в состоянии hasPuck=true и без цели. При достижении логики Update он будет повторно пытаться найти ячейку. Это не обязательно авария, но сценарий отсутствия свободной ячейки стоит предусмотреть.

**19. В ручном режиме массив шайб задаётся вручную.**

Если забыть добавить шайбу в Inspector, ручной режим не сможет её подобрать, даже если она присутствует в сцене.

**20. ShowTime и UI-ссылки не защищены от null.**

Timer Text, Result Text и Result Panel обязательны. Ошибка назначения вызовет NullReferenceException.

### 6.4 Что не следует менять без необходимости

- Проверенные SteamVR Input Actions и их bindings.
- Логику отсоединения объекта от руки SteamVR.
- Последовательность установки детали: detach → отключение взаимодействия/физики → установка флага → parent → локальное выравнивание.
- Проверенные настройки NavMeshAgent, в том числе Base Offset = -0.07.
- Проверенную механику сортировки шайб и соответствие номеров.
- Путь запуска через RobotAssembly, поскольку он защищает запуск проверкой сборки.

Любое изменение следует делать в отдельной копии/версии, а не поверх единственного рабочего релиза.

## 7. Порядок работы игровых механик

### 7.1 Сборка робота
1. Игрок берёт деталь через SteamVR Interactable.
2. Подносит её к подходящей точке крепления.
3. RobotMountPoint проверяет тип, расстояние и факт удержания в руке.
4. Деталь отсоединяется от руки.
5. Interactable и Throwable отключаются.
6. Rigidbody переводится в кинематический режим, гравитация отключается.
7. Collider детали отключаются.
8. RobotPart помечается установленной.
9. Деталь становится дочерней точки и выравнивается по ней.

### 7.2 Проверка готовности
RobotAssembly проверяет:
- Motor установлен;
- PowerSupply установлен;
- Manipulator установлен;
- Tracks установлены;
- StartZone сообщает, что зона занята.

Если хотя бы одно условие не выполнено, запуск прекращается без сообщения об ошибке. Это нормальный отказ по текущей логике.

### 7.3 Автоматическая сортировка
1. Контроллер получает все активные шайбы и ячейки.
2. Ищет ближайшую шайбу, которая не отсортирована, не переносится и имеет свободную ячейку с таким же номером.
3. Идёт к pickupPoint или к самой шайбе.
4. При достижении прикрепляет шайбу к puckPoint и выключает её коллайдеры.
5. Ищет ближайшую свободную ячейку с совпадающим номером.
6. Идёт к approachPoint или dropPoint.
7. При достижении помещает шайбу в dropPoint.
8. Помечает шайбу и ячейку заполненными.
9. Сообщает GameManager об успехе и повторяет цикл.

### 7.4 Ручная сортировка
1. После старта считывается ввод левой руки.
2. Forward/Backward перемещают робота, Left/Right поворачивают.
3. Magnet запускает поиск ближайшей шайбы в grabDistance.
4. Шайба прикрепляется к carryPoint, физика и Collider отключаются.
5. Release отсоединяет шайбу, возвращает Rigidbody и Collider.
6. Когда шайба входит в Trigger подходящей ячейки, PuckSlot проверяет номер и регистрирует сортировку.

### 7.5 Завершение
- Если число зарегистрированных шайб достигло totalPucks, GameManager завершает раунд.
- Если таймер достиг нуля, GameManager также завершает раунд.
- Контроллеры получают StopRobot.
- На экране отображается количество отсортированных шайб.
- Панель результата становится активной.
- Restart перезагружает текущую сцену.

## 8. Словарь важных терминов

| Термин | Значение |
|---|---|
| GameObject | Объект сцены Unity |
| Component | Компонент, добавленный на GameObject |
| MonoBehaviour | Базовый класс Unity-скриптов |
| Transform | Позиция, поворот и масштаб объекта |
| Parent / Child | Родительский и дочерний объект в Hierarchy |
| Rigidbody | Компонент физического тела |
| isKinematic | Перевод Rigidbody под управление Transform/анимации, а не обычной динамической физики |
| Collider | Физическая форма столкновения |
| Is Trigger | Режим Collider, который сообщает о пересечении, не создавая обычного физического препятствия |
| NavMesh | Поверхность, по которой может перемещаться навигационный агент |
| NavMeshAgent | Компонент поиска пути и движения по NavMesh |
| SteamVR Input Action | Именованное действие ввода, привязанное к кнопке/оси VR-контроллера |
| Interactable | Компонент SteamVR Interaction System для взаимодействия с объектом |
| Throwable | Компонент SteamVR Interaction System для поведения бросаемого объекта |
| TMP_Text | Компонент текстового UI TextMeshPro |
| Inspector | Панель настройки компонентов и ссылок в Unity |
| Prefab | Сохранённый шаблон GameObject |
| Build Settings | Список сцен, включённых в сборку приложения |
| NullReferenceException | Ошибка обращения к отсутствующей ссылке |

## 9. Итог аудита

Релиз 11.0 содержит компактную систему из девяти скриптов с понятным разделением обязанностей: сборка робота, стартовая проверка, два режима управления, сортировка шайб и игровой менеджер.

Ключевые условия корректной работы:
1. Кнопка запуска вызывает RobotAssembly, а не контроллер напрямую.
2. Все четыре точки крепления имеют правильные типы и ссылки.
3. StartZone настроена как Trigger.
4. SteamVR Input Actions существуют и привязаны к левой руке.
5. В автоматическом режиме настроены NavMeshAgent, NavMesh, puckPoint и GameManager.
6. В ручном режиме заполнен массив шайб и назначен carryPoint.
7. Номера шайб и ячеек совпадают.
8. Все ячейки имеют Trigger, GameManager и Drop Point.
9. Все обязательные ссылки Inspector назначены.

**Общий вывод:** по коду архитектура релиза последовательна и достаточно проста. Основные риски сосредоточены не в самой схеме механик, а в назначении ссылок Inspector, конфигурации SteamVR/Physics/NavMesh и обработке редких сценариев: остановка при переносе шайбы, отсутствие Rigidbody, отсутствие ячейки, повторный старт без перезагрузки сцены и посторонние Collider в стартовой зоне.

Документ описывает фактический код папки «Релиз 11.0». Он не заменяет проверку Unity-сцены и Project Settings: точные версии пакетов и все значения компонентов можно зафиксировать только по самому Unity-проекту.
